Module 03: Amazon VPC

⏱️ Est. Time: 60 Mins ⚙️ Services: VPC, Subnets, IGW 💰 Cost: Free Tier Eligible

Core Concept & Real-World Utility

VPC gives you complete control over your virtual networking environment. You define the logical network topology including IP address ranges (CIDR), subnets, route tables, and gateways. It ensures strict network isolation, preventing unauthorized external access to internal enterprise components.

Architecture Integration

We implemented a classic Two-Tier Architecture. The Web Tier (EC2) sits in a Public Subnet with a direct route to the Internet Gateway. The Database Tier (RDS) sits in a Private Subnet with no public IP, meaning hackers cannot even attempt to scan or breach the database from the public internet.

⚖️ Architecture Trade-off Analysis

Custom VPC Isolation vs. Default VPC Simplicity: Building a custom VPC with isolated private subnets provides maximum security and compliance. The trade-off is significantly higher networking configuration complexity (managing route tables, CIDR blocks, and gateway attachments).

Terminal / Code Execution

When automating network infrastructure, engineers use the AWS CLI or Terraform. Here is the raw CLI execution to create a VPC, an IGW, and attach them together.

# Step 1: Create the VPC and capture the output VpcId
aws ec2 create-vpc --cidr-block 10.0.0.0/16

# Step 2: Create the Internet Gateway
aws ec2 create-internet-gateway

# Step 3: Attach the IGW to the VPC
aws ec2 attach-internet-gateway \
    --vpc-id vpc-0a1b2c3d4e5f6g7h8 \
    --internet-gateway-id igw-0123456789abcdef0

Debugging & Troubleshooting

Error: EC2 instance in a custom VPC cannot be reached via SSH.
Check the triad of public networking: 1) Does the instance have a Public IP? 2) Is the IGW firmly attached to the VPC? 3) Does the Route Table associated with that specific subnet have a 0.0.0.0/0 route pointing to the IGW?
