Module 01: Amazon EC2

⏱️ Est. Time: 45 Mins ⚙️ Services: EC2, EBS, VPC 💰 Cost: Free Tier Eligible

Core Concept & Real-World Utility

EC2 is the foundational compute unit of AWS. It provides resizable, on-demand virtual machines (instances). In enterprise architectures, EC2 handles everything from hosting stateless microservices and backend APIs to running heavy data-processing algorithms.

Architecture Integration

In our campus portal project, the EC2 instance acts as the primary web application server. It resides inside a public subnet (to receive HTTP requests directly, prior to adding an ALB) and executes a Python/FastAPI backend configured behind an Nginx reverse proxy.

⚖️ Architecture Trade-off Analysis

EC2 vs. Serverless Compute (Lambda): Choosing a persistent EC2 instance guarantees zero cold-start latency and full root shell access for custom database connection pooling. However, unlike serverless options that scale to zero cost when idle, EC2 incurs continuous hourly charges 24/7 and requires manual OS security patching.

Terminal / Code Execution

Connecting to the EC2 instance via the terminal requires adjusting the key permissions first to prevent 'Unprotected Private Key File' errors thrown by the SSH client.

# Step 1: Restrict permissions on the downloaded key file
chmod 400 itm-lab-key.pem

# Step 2: SSH into the public DNS of the EC2 instance
ssh -i "itm-lab-key.pem" ubuntu@ec2-198-51-100-1.compute-1.amazonaws.com

# Step 3: Verify the Nginx installation from our User Data script
systemctl status nginx

⚠️ AWS Free Tier Cost Warning

Always ensure you select resources marked "Free tier eligible". Leaving non-eligible resources running (like NAT Gateways, Elastic IPs not attached to running instances, or t3.large instances) will result in immediate hourly billing to your AWS account. Terminate instances when the lab is complete.

Debugging & Troubleshooting

Error: Connection Refused / Timeout on Port 80.
If the terminal SSH works but the browser cannot load the website, the issue is the Security Group. Verify that an Inbound Rule explicitly allows TCP Port 80 from 0.0.0.0/0. EC2 instances block all inbound traffic implicitly by default.
