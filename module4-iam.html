Module 04: AWS IAM

⏱️ Est. Time: 45 Mins ⚙️ Services: IAM, EC2 💰 Cost: Free Tier Eligible

Core Concept & Real-World Utility

IAM is the central nervous system for cloud security. It handles Authentication (verifying identities) and Authorization (granting specific permissions). IAM strictly enforces the 'Principle of Least Privilege', ensuring that a user or application can only access the exact resources required to function.

Architecture Integration

We use IAM Roles for our EC2 instances instead of hardcoding AWS Access Keys in our application code. When our FastAPI backend needs to read a file from S3, the boto3 SDK automatically assumes the IAM Role attached to the EC2 instance, retrieving temporary, auto-rotating security credentials.

⚖️ Architecture Trade-off Analysis

IAM Roles vs. Hardcoded Access Keys: Using IAM Instance Profiles eliminates the catastrophic risk of leaking plain-text credentials inside application repository files. The trade-off is a steeper learning curve when configuring JSON permission boundaries and trust relationships.

Terminal / Code Execution

This JSON policy demonstrates least privilege. Instead of granting 's3:*' across the whole account, it explicitly lists allowed actions and restricts them to a single bucket's Amazon Resource Name (ARN).

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:ListBucket",
                "s3:PutObject",
                "s3:GetObject"
            ],
            "Resource": [
                "arn:aws:s3:::itm-lab-assets-12345",
                "arn:aws:s3:::itm-lab-assets-12345/*"
            ]
        }
    ]
}

Debugging & Troubleshooting

Error: botocore.exceptions.ClientError: Access Denied.
If your application code throws an Access Denied error when attempting to call AWS APIs, the IAM Role attached to the EC2 instance lacks the specific `Action` in its policy, or the specific `Resource` ARN is typed incorrectly. Verify the IAM Policy Simulator.
