Module 05: Amazon RDS

⏱️ Est. Time: 50 Mins ⚙️ Services: RDS, PostgreSQL, VPC 💰 Cost: Free Tier Eligible

Core Concept & Real-World Utility

RDS removes the operational burden of managing relational databases. It abstracts away OS patching, database engine updates, automated daily snapshots, and complex master-standby replication setups. Engineers can deploy MySQL, PostgreSQL, or Aurora with high availability in a few clicks.

Architecture Integration

We deployed a PostgreSQL RDS instance into the Private Subnets of our VPC. The database handles all ACID-compliant transactional data. It is completely isolated from the internet; its Security Group only permits inbound port 5432 connections originating from the EC2 Web Server's Security Group.

⚖️ Architecture Trade-off Analysis

Managed RDS vs. Self-Hosted DB on EC2: RDS automates high availability failover, OS patches, and daily backups, saving hundreds of hours of DevOps labor. However, it is more expensive than running PostgreSQL directly on an EC2 instance and abstracts away low-level filesystem kernel tuning access.

Terminal / Code Execution

Once the database is up, you must connect via an EC2 instance in the same VPC (acting as a Bastion Host) to initialize the schema and run migrations.

# Step 1: Install PostgreSQL client tools on the EC2 web server
sudo apt-get install postgresql-client -y

# Step 2: Connect using the internal DNS writer endpoint provided by RDS
psql --host=itm-db-1.c3x...ap-south-1.rds.amazonaws.com \
     --port=5432 \
     --username=postgres_admin \
     --dbname=postgres

Debugging & Troubleshooting

Error: psql command times out indefinitely without a password prompt.
This is a classic Security Group configuration failure. The database is actively dropping your packets. Go to the RDS Security Group's Inbound Rules and ensure the Source field strictly references the Security Group ID of the connecting EC2 instance.
