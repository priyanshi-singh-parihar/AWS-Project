Module 07: Amazon Route 53

⏱️ Est. Time: 30 Mins ⚙️ Services: Route 53, S3, EC2 💰 Cost: Free Tier Eligible

Core Concept & Real-World Utility

Route 53 is a highly available, globally distributed Domain Name System (DNS) web service. It acts as the internet's phonebook, translating domain names (e.g., `itm.edu`) into numeric IP addresses. It also provides advanced traffic flow rules like weighted routing, latency-based routing, and active health checks.

Architecture Integration

Route 53 is the entry point for all user traffic. Instead of giving users an ugly Load Balancer URL, we map a custom domain. By configuring an Active-Passive Failover policy, Route 53 continuously monitors our EC2 servers. If they crash, DNS automatically flips and routes users to a static 'Under Maintenance' page on S3.

⚖️ Architecture Trade-off Analysis

Route 53 Managed DNS vs. Registrar DNS: Leveraging Route 53 allows high-speed Anycast DNS routing and instant integration with AWS health checks and ALBs. The trade-off is a minor monthly hosted zone fee and managing name server delegations outside your registrar.

Terminal / Code Execution

DNS propagation can take time. Developers use the `dig` command-line utility to query DNS records directly from nameservers, bypassing local machine caching.

# Query local ISP to see what IP the domain currently resolves to
dig +short example.com

# Query the specific AWS Route 53 nameserver directly to verify our changes
dig @ns-123.awsdns-45.com example.com A

# Check the CNAME or ALIAS records for a subdomain
dig +short api.example.com CNAME

Debugging & Troubleshooting

Error: Site cannot be reached (DNS_PROBE_FINISHED_NXDOMAIN).
If your browser throws an NXDOMAIN error immediately after setup, your domain registrar is likely still pointing to its default parked nameservers. You must replace them with the four specific NS records generated by your Route 53 Hosted Zone. Full propagation can take up to 24-48 hours.
