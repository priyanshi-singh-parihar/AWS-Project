Module 02: Amazon S3

⏱️ Est. Time: 30 Mins ⚙️ Services: S3, IAM 💰 Cost: Free Tier Eligible

Core Concept & Real-World Utility

S3 is a highly durable, infinitely scalable object storage service. Unlike block storage (EBS) which must be attached to a single EC2 instance, S3 stores data as 'objects' accessible via HTTP APIs. It provides 99.999999999% (11 9's) of data durability across multiple availability zones.

Architecture Integration

S3 decouples our static asset delivery from our backend compute. Instead of serving heavy PDF documents and user profile pictures from our EC2 instance (which wastes CPU and bandwidth), S3 handles all static file delivery directly to the end users.

⚖️ Architecture Trade-off Analysis

S3 Static Hosting vs. Server-Rendered Storage: S3 provides 11 nines of durability and instant global scaling without managing server disks. However, it is strictly limited to static file distribution and cannot execute server-side application logic or dynamic runtime rendering natively.

Terminal / Code Execution

The Bucket Policy is the critical security boundary. This policy explicitly allows any anonymous user on the internet to read files from the bucket, but denies any write or delete actions.

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::itm-lab-assets-12345/*"
        }
    ]
}

Debugging & Troubleshooting

Error: 403 Access Denied on Static Endpoint.
Even if BPA is disabled, AWS implicitly denies read requests. If your website shows an XML 403 error, verify your JSON Bucket Policy. Ensure the Resource ARN ends with /* to apply to the objects *inside* the bucket, not just the bucket itself.
